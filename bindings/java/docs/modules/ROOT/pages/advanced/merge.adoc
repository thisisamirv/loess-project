= Merge Strategies

How overlapping chunk boundaries are reconciled in Streaming mode.

== Overview

`StreamingLoess` processes data in fixed-size chunks with a configurable overlap. Points inside the overlap zone are fitted twice — once by the left chunk and once by the right chunk. `mergeStrategy` decides how those two estimates are combined into a single output value.

[source,text]
----
Chunk A:   [=========|=====]
Chunk B:            [=====|=========]
Overlap:            [=====]
                      ^
                mergeStrategy
                applied here
----

[cols="1,1,1,1",options="header"]
|===
|Strategy |Method |Robustness |Speed

|`"average"` |Simple mean of both estimates |Low |Fastest
|`"take_first"` |Left-chunk estimate only |Low |Fastest
|`"take_last"` |Right-chunk estimate only |Low |Fastest
|`"weighted_average"` |Distance-weighted mean |High |Moderate
|===

'''

== Average

Takes the arithmetic mean of the left-chunk and right-chunk estimates in the overlap region. Fast and sufficient when both chunks have similar smoothing quality.

*Use when*: Chunks are large and the overlap region has uniform data density.

[source,java]
----
import fastloess.Result;
import fastloess.StreamingLoess;
import fastloess.StreamingOptions;

public class Example {
    public static void main(String[] args) {
        int n = 100;
        double[] x = new double[n];
        double[] y = new double[n];
        for (int i = 0; i < n; i++) {
            x[i] = i * 2 * Math.PI / (n - 1);
            y[i] = Math.sin(x[i]) + 0.1;
        }

        StreamingOptions options = StreamingOptions.builder().chunkSize(60).overlap(20).mergeStrategy("average").build();

        try (StreamingLoess model = new StreamingLoess(options)) {
            model.processChunk(java.util.Arrays.copyOfRange(x, 0, 60), java.util.Arrays.copyOfRange(y, 0, 60));
            // The second chunk's overlap region (its first 20 points) is where
            // mergeStrategy actually blends the two chunks' estimates.
            Result result = model.processChunk(java.util.Arrays.copyOfRange(x, 60, x.length), java.util.Arrays.copyOfRange(y, 60, y.length));
            System.out.println("Merged value in overlap region (average): " + result.y()[5]);
        }
    }
}
----

[source,console]
----
Merged value in overlap region (average): 0.32485200482802645
----

'''

== Take First

Keeps only the left-chunk estimate in the overlap zone and discards the right-chunk estimate. Produces a definitive, non-revised output as soon as the right boundary of each chunk is reached.

*Use when*: You need final output values immediately after each chunk (no look-ahead revision); left-chunk data quality is higher.

[source,java]
----
import fastloess.Result;
import fastloess.StreamingLoess;
import fastloess.StreamingOptions;

public class Example {
    public static void main(String[] args) {
        int n = 100;
        double[] x = new double[n];
        double[] y = new double[n];
        for (int i = 0; i < n; i++) {
            x[i] = i * 2 * Math.PI / (n - 1);
            y[i] = Math.sin(x[i]) + 0.1;
        }

        StreamingOptions options = StreamingOptions.builder().chunkSize(60).overlap(20).mergeStrategy("take_first").build();

        try (StreamingLoess model = new StreamingLoess(options)) {
            model.processChunk(java.util.Arrays.copyOfRange(x, 0, 60), java.util.Arrays.copyOfRange(y, 0, 60));
            Result result = model.processChunk(java.util.Arrays.copyOfRange(x, 60, x.length), java.util.Arrays.copyOfRange(y, 60, y.length));
            System.out.println("Merged value in overlap region (take_first): " + result.y()[5]);
        }
    }
}
----

[source,console]
----
Merged value in overlap region (take_first): 0.3537634002807739
----

'''

== Take Last

Keeps only the right-chunk estimate in the overlap zone. The right chunk sees more of the surrounding data, so its fit can be more accurate near the left boundary of the new chunk.

*Use when*: Right-chunk context improves overlap quality; you are post-processing complete data rather than streaming live.

[source,java]
----
import fastloess.Result;
import fastloess.StreamingLoess;
import fastloess.StreamingOptions;

public class Example {
    public static void main(String[] args) {
        int n = 100;
        double[] x = new double[n];
        double[] y = new double[n];
        for (int i = 0; i < n; i++) {
            x[i] = i * 2 * Math.PI / (n - 1);
            y[i] = Math.sin(x[i]) + 0.1;
        }

        StreamingOptions options = StreamingOptions.builder().chunkSize(60).overlap(20).mergeStrategy("take_last").build();

        try (StreamingLoess model = new StreamingLoess(options)) {
            model.processChunk(java.util.Arrays.copyOfRange(x, 0, 60), java.util.Arrays.copyOfRange(y, 0, 60));
            Result result = model.processChunk(java.util.Arrays.copyOfRange(x, 60, x.length), java.util.Arrays.copyOfRange(y, 60, y.length));
            System.out.println("Merged value in overlap region (take_last): " + result.y()[5]);
        }
    }
}
----

== Weighted Average

Assigns each overlap point a weight proportional to its proximity to the centre of its respective chunk: points near the left-chunk centre get higher left weight; points near the right-chunk centre get higher right weight. This produces the smoothest transition across chunk boundaries.

[stem]
++++
\hat{y} = \frac{w_L \hat{y}_L + w_R \hat{y}_R}{w_L + w_R}
++++

where stem:[w_L] and stem:[w_R] are linear distance weights from the chunk centres.

*Use when*: Minimising boundary artefacts is more important than speed; moderate overlap (10–20 % of chunk size).

[source,java]
----
import fastloess.Result;
import fastloess.StreamingLoess;
import fastloess.StreamingOptions;

public class Example {
    public static void main(String[] args) {
        int n = 100;
        double[] x = new double[n];
        double[] y = new double[n];
        for (int i = 0; i < n; i++) {
            x[i] = i * 2 * Math.PI / (n - 1);
            y[i] = Math.sin(x[i]) + 0.1;
        }

        StreamingOptions options = StreamingOptions.builder().chunkSize(60).overlap(20).mergeStrategy("weighted_average").build(); // Default merge strategy

        try (StreamingLoess model = new StreamingLoess(options)) {
            model.processChunk(java.util.Arrays.copyOfRange(x, 0, 60), java.util.Arrays.copyOfRange(y, 0, 60));
            Result result = model.processChunk(java.util.Arrays.copyOfRange(x, 60, x.length), java.util.Arrays.copyOfRange(y, 60, y.length));
            System.out.println("Merged value in overlap region (weighted_average): " + result.y()[5]);
        }
    }
}
----

[source,console]
----
Merged value in overlap region (weighted_average): 0.3393077025544002
----

== Choosing a Strategy

[cols="1,1",options="header"]
|===
|Situation |Recommended Strategy

|General purpose |`"weighted_average"`
|Maximum throughput |`"average"`
|Immediate finalised output |`"take_first"`
|Post-processing, right context better |`"take_last"`
|Minimising boundary artefacts |`"weighted_average"`
|===

[NOTE]
====
*Overlap size matters:* A larger overlap gives the merge strategy more room to blend, reducing boundary artefacts regardless of the strategy chosen. A good starting point is 10 % of `chunkSize`.
====

All examples above use the same 100-point noisy sine wave (see xref:../weighting/kernels.adoc#choosing-a-kernel[Weight Functions] for the generation code).
